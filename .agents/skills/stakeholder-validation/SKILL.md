# Stakeholder Validation

## Process

1. Identify the stakeholder group and purpose of review.
2. Use README role paths to select the shortest useful reading path.
3. Prepare a review agenda with decisions, assumptions, and questions.
4. Capture feedback in `09-contributor-workspace/review-requests/`.
5. Promote validated feedback to canonical files.
6. Add decisions and assumptions to the right registers.

## Recommended Review Order

1. Internal operators: Filip, Mikolaj, Edward.
2. Trusted construction/operator advisor.
3. Attorney, CPA, insurance advisor.
4. Referral partners.
5. Potential owner-partners.
6. Investors only after proof gaps are understood.

## Guardrails

- Present the plan as Version 0.1 for validation, not a finished plan.
- Do not use investor-facing language with owner-partners if it could make the approach feel extractive.
- Separate feedback into: accepted, rejected, needs evidence, and future consideration.
